## 6. 리버스 결론 — "짐작이었다"의 증거

```
짐작:  폰에서 뭔가 = APK (550커밋 빌드지옥 + 9앱 삽질)
정밀:  폰에서 뭔가 = ADB(브릿지) → 웹앱+로컬서버(표준) → APK(예외 3가지)

APK Lab의 진짜 산출물은 9개 앱이 아니라
"왜 APK가 아닌가"를 증명한 926커밋의 반례 기록이다.
```

**ADB를 알기 전엔 전부 짐작이었다:**
- 짐작 ① "네이티브 앱이 폰 제어의 답" → 사실 ADB+파일+웹앱이 95% 커버
- 짐작 ② "온디바이스 AI를 앱에 심자" → 성능/과금 한계로 철회 (5/31)
- 짐작 ③ "PWA가 정답" → 1/18 웹 바로가기로 단순화 → 8월 로컬서버로 재해석

**지금의 정밀:**
- ADB = 상시 브릿지 (Shizuku TCP5900 · sshd · 메시 · 워치독)
- 웹앱+로컬서버 = 소비재 표준 (Toolkit 카드)
- APK = 예외 3가지만 (백그라운드 · 저수준 HW · 외부 유통)

## 7. 왜 "지금이 완벽한 모멘텀"인가

926커밋의 삽질이 **ICM-STANDARD §8-4 한 단락**으로 응축된 순간이다.
짐작이 끝나고 정밀이 시작됐다. 이제 새 작업은:
1. ICM 아이템 등록 → 2. 두 타입 분기(클릭 vs 연산) → 3. 웹앱/파이프라인 선택 → 4. Fab 실행

더 이상 "APK 만들까?"라고 묻지 않는다.
**"웹앱으로 되나?"가 첫 질문이고, "ADB로 되나?"가 둘째, "APK"는 마지막이다.**
